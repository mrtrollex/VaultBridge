# RC hardening repair candidate

This repair branch starts at frozen source
`9076482a768cb6db316f8c191118c7069d77208f`. The published/frozen RC is unchanged and
remains **NO-GO**. This document records source repairs, not a qualified replacement
image, release, deployment or upgrade/rollback canary.

## Confirmed causes and bounded repairs

### Legacy MCP discovery

The shared output-schema union contained object alternatives but omitted the root
`type: object`. Both MCP SDK 2.2 and 2.3 reject that shape when serializing legacy
`tools/list`, after successfully negotiating the legacy connection. The error is
in VaultBridge's generated schema, not the client's initialization request.

`schema_union` now preserves the object root alongside its existing alternatives
and definitions. Tool names, opt-in write registration, payloads, policy dispatch
and protocol 2026-07-28 remain unchanged. The regression exercises actual SDK
legacy/modern discovery and scoped Query, for legacy/named composition with writes
enabled/disabled. The same tests run with both SDK versions. Additional serializer
checks cover 2025-03-26, 2025-06-18, 2025-11-25 and 2026-07-28.

### Native watcher reconstruction test

Native `watcher.start()` acknowledges registration/liveness, while recursive
coverage restoration can arrive later. `scheduler.wait()` waits for quiescence;
it cannot prove that a not-yet-restored coverage generation has submitted its full
reconciliation. The test asserted completion without establishing that ordering.

The corrected test waits under the existing scheduler condition for
`coverage_restored == coverage_revision`, using the existing five-second bound,
before its final scheduler wait. It retains the original debt assertion and adds
checks for reconciled coverage, no paused owner and no monitoring recovery. No
production watcher code, sleeps, timeout increases or skips are added.

An external diagnostic plugin delays the actual native restoration receipt. The
frozen test fails its original assertion; the repaired test passes only after the
same real receipt is delivered. Suppressing restoration still fails the repaired
test's acknowledgement assertion. Expected negative-control failures are retained
as failed pytest results, not converted to skips or release passes.

### SQLite WAL/SHM after MCP EOF

A real mode=ro SQLite reader can recreate WAL/SHM for a WAL-format database even
after the last writer closed cleanly. Closing that reader releases its connection
but need not remove these files. Thus the qualification did not prove a leaked
connection; it exposed a missing transition from live reads to immutable stopped
storage. The immutable profile correctly rejects sidecars and remains unchanged.

After the serving runtime fences ingress, stops producers/scheduler and drains
admission/retained connections, the default repository now finalizes validated
existing storage through a registered mode=rw connection with SQL query-only
enabled. SQLite's own last-close processing retires WAL/SHM. No manual unlink,
schema creation, journal-mode switch, binding replacement or new cross-process
coordination is introduced. Research/disabled/immutable profiles do not acquire
this writable cleanup authority. Unavailable/foreign storage is left untouched.

Connection-close failures retain the exact connection for explicit same-runtime
retry. If SQLite cannot retire sidecars because another reader remains, shutdown
does not report a completed offline transition. The original exclusive-owner
operational contract still applies; this is not a multi-process locking guarantee.

Regressions cover actual semantic retrieval followed by real module stdio EOF,
immutable SQLite integrity/readiness afterward, unchanged chunks, close failure
before and after actual release, retained-object retry, missing/rejected storage
and a live peer that blocks completion until its actual release. Embeddings in
these tests are synthetic; no external service or model download is used.

repairs on Windows (SDK 2.2) and native WSL/Linux (SDK 2.3). Original qualification
vaults, databases, model cache, symlinks, logs and preserved SQLite evidence are not
used as writable repair fixtures. A read-only Linux inventory matches all 41
original file/symlink records, including the original residual sidecars. The
serving container remains stopped.

Required source validation follows `agent_task.py -> agent_finish.py -> separate
fresh review`. The selector's actual changed-file decision owns automated check
selection; its output is retained rather than treating forbidden image builds as
successful checks. No Docker build, publication, stable-tag change, promotion or
canary is performed by this repair task.
