# VB-156B confirmed protected-read 401 repair

The original `ScopedClient.get()` awaited `response.json()` before checking HTTP
401. Empty, malformed, truncated or non-JSON bodies therefore threw before the
coordinated cleanup, leaving selection/discovery/capability metadata authenticated.
The actual-module/native-session malformed-status reproducer failed before the fix:
`red.log`, `red.xml`, `red-traces/` (1 expected failing reproduction).

The only production change is in `app/ui/assets/scoped-client.js`: handle HTTP 401
before JSON parsing, first preserving the captured session epoch and intent/journal
snapshot check, then invoking the unchanged NamedSession.unauthorized(snapshot).
Its existing synchronous blank and under-Web-Lock revalidation/delete protocol
remain the owners of state erasure and cookie cleanup. Non-401 parsing and status
mapping, protected/session schemas, legacy controllers, cookie attributes, headers,
CSRF guards and Bearer precedence are unchanged. No body text is displayed.

The only other source change is `tests/e2e/test_named_dashboard.py`. The temporary
native-server streaming experiments were fully reverted; `named_server.py` has no
repair delta. `repair.patch` and `scope.json` record this pass separately from the
large pre-existing VB-156B working tree. ADR 0011 and other production files match
the retained source hashes.
